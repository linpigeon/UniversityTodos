# 学习通作业获取实现代码复用说明

> 本文按当前仓库实现整理，供在其他 C#/.NET 项目中复用学习通作业、考试和课程未完成任务点获取功能。
>
> 学习通接口并非公开稳定契约，页面或接口调整后需要同步修改解析规则。不要把真实账号 Cookie 写入源码或随本文分享。

## 1. 整体结构

```text
学习通 Cookie
    ↓
ChaoxingApiClient
    ├─ 获取作业列表：HTML → ChaoxingTask
    ├─ 获取考试列表：HTML → ChaoxingTask
    ├─ 获取课程列表：JSON → ChaoxingCourse
    └─ 逐课获取未完成任务点：HTML → 课程汇总
    ↓
ChaoxingSyncService
    ├─ 状态、稳定 ID、站内链接映射
    ├─ 相对剩余时间 → 可推算的截止时间
    └─ 单课失败降级、旧缓存保留
    ↓
TodoItem / ChaoxingCourse
```

## 2. 需要复制的代码

| 文件 | 作用 | 是否必需 |
|---|---|---|
| `UniversityTodos/Services/ChaoxingApiClient.cs` | HTTP 请求、登录失效检测、作业/考试/课程/任务点解析 | **核心必需** |
| `UniversityTodos/Services/ChaoxingUrls.cs` | 构造课程页 URL，校验课程三元组 | 复制整个 ApiClient 时需要 |
| `UniversityTodos/Services/ChaoxingSyncService.cs` | 把接口结果转换为统一待办和课程模型 | 建议 |
| `UniversityTodos/Models/TodoItem.cs` | 统一待办模型，含相对截止时间还原 | 使用 SyncService 时需要 |
| `UniversityTodos/Models/ChaoxingCourse.cs` | 课程任务点汇总及叶子明细模型 | 需要任务点功能时复制 |
| `UniversityTodos/Models/YktEnums.cs` | `TodoKind`、`TodoStatus` 等枚举 | 使用现有 TodoItem 时需要 |

核心代码只使用 `HttpClient`、`System.Text.Json`、正则等 .NET 内置能力，没有第三方抓取库。当前项目目标框架是 .NET 10；低版本复用时，可能需要调整主构造函数、集合表达式和 `GeneratedRegex` 等语法。

复制后需要按目标项目调整命名空间。`ChaoxingApiClient` 中与课程任务点有关的代码依赖 `ChaoxingUrls`；如果只需要作业和考试，也可以只保留对应记录、请求方法和公共 `GetAsync` 方法。

### 2.1 可选的登录与持久化代码

| 文件 | 作用 |
|---|---|
| `UniversityTodos/Services/ChaoxingLoginService.cs` | 从 Avalonia WebView 捕获学习通 Cookie，存在 `_uid` 即认为登录成功 |
| `UniversityTodos/Views/ChaoxingLoginView.axaml.cs` | 导航完成后自动捕获会话 |
| `UniversityTodos/Services/ChaoxingSessionStore.cs` | 保存会话，Windows 使用 DPAPI 加密 |
| `UniversityTodos.Desktop/ChaoxingCheck.cs` | 使用本机会话运行课程任务点在线自检 |

这些不是纯抓取功能的必需部分。尤其 `ChaoxingSessionStore` 还依赖 `AppPaths`、`Dpapi`、`AppJsonContext` 等，目标项目已有登录或存储方案时不必照搬。

## 3. 实际使用的接口

| 功能 | 请求 | 返回及解析位置 |
|---|---|---|
| 作业列表 | `GET https://mooc1-api.chaoxing.com/work/stu-work` | HTML，解析 `<li data="...">` 和 `aria-label`，见 `ChaoxingApiClient.GetHomeworkAsync` |
| 考试列表 | `GET https://mooc1-api.chaoxing.com/exam-ans/exam/phone/examcode` | HTML，解析考试深链和单引号 `aria-label`，见 `ChaoxingApiClient.GetExamsAsync` |
| 课程列表 | `GET https://mooc1-api.chaoxing.com/mycourse/backclazzdata?view=json&rss=1` | JSON，见 `ChaoxingApiClient.GetCoursesAsync` |
| 课程未完成任务点 | `GET https://mooc1-2.chaoxing.com/visit/stucoursemiddle?courseid={courseId}&clazzid={clazzId}&vc=1&cpi={personId}` | HTML 章节树，见 `ChaoxingApiClient.GetPendingTaskPointsAsync` |

所有请求都需要：

- 手工设置完整 `Cookie` 请求头。
- 使用桌面 Chrome `User-Agent`。
- 设置对应 `Referer`。
- 开启自动解压，超时时间为 30 秒。
- 不能只看 HTTP 200：登录失效会返回登录页 HTML。当前通过 `<title>登录</title>` 或 `passport2.chaoxing.com/login` 判断，见 `ChaoxingApiClient.GetAsync`。

部分新版 JSON 接口需要 `enc` 参数，因此当前实现选择不要求 `enc` 的服务端渲染页面。作业和考试解析依赖 HTML 结构及 `aria-label` 文本，站点改版后需要重新核对正则。

## 4. 最小调用示例

只需要原始抓取结果时，直接使用 `ChaoxingApiClient`：

```csharp
using UniversityTodos.Services;

// 由目标项目自己的登录流程提供，不要硬编码或分享真实 Cookie。
string cookieHeader = GetCookieFromYourOwnLoginFlow();

using var api = new ChaoxingApiClient(cookieHeader);

var homework = await api.GetHomeworkAsync();
var exams = await api.GetExamsAsync();

foreach (var task in homework.Concat(exams))
{
    Console.WriteLine(
        $"{task.Title} | {task.CourseName} | {task.Status} | " +
        $"{task.Remaining} | {task.SourceUrl}");
}

var courses = await api.GetCoursesAsync();

foreach (var course in courses)
{
    var points = await api.GetPendingTaskPointsAsync(
        course.CourseId,
        course.ClazzId,
        course.PersonId);

    Console.WriteLine($"{course.CourseName}：{points.PendingTotal} 个未完成任务点");
}
```

如果同时复制了同步层和模型，可以直接获得统一待办：

```csharp
var (items, forCache) = await ChaoxingSyncService.SyncAsync(
    cookieHeader,
    DateTimeOffset.Now);

foreach (var item in items)
{
    Console.WriteLine(
        $"{item.Id} | {item.Title} | {item.StatusText} | {item.EffectiveDueAt}");
}
```

`items` 用于本次界面展示；`forCache` 保留相对截止时间的缓存形态。课程任务点可以单独同步：

```csharp
var (courses, warnings) = await ChaoxingSyncService.SyncCoursesAsync(
    cookieHeader,
    progress: null,
    previous: null);
```

## 5. 数据映射规则

### 5.1 稳定 ID

- 作业：`hw-cx-work-{taskrefId}`
- 考试：`hw-cx-exam-{taskrefId}`

稳定 ID 用于去重、缓存和新作业判定，不要使用标题作为唯一键。

### 5.2 状态映射

| 页面状态 | 统一状态 |
|---|---|
| `未提交`、`未交` | `NotStarted` |
| `待批阅` | `InProgress`，表示学生已提交、等待批阅 |
| `已批阅`、`已完成`、`已结束` | `Completed` |
| 其他 | `Unknown` |

考试页面通常没有单独的课程字段，当前实现将考试名称同时作为标题和课程名。

### 5.3 相对截止时间

学习通页面只提供“剩余 X 天 X 小时 X 分钟”，不提供绝对截止时间。当前模型采用：

```text
EffectiveDueAt = DueAt ?? (DeadlineAnchor + RemainingAtSync)
```

缓存应保存同步基准和当时的相对剩余量，不要只保存一次推算出的绝对时间，否则应用长时间未打开后，缓存中的倒计时可能失真。下游排序、逾期判断和倒计时统一读取 `EffectiveDueAt`。

## 6. 复用时必须保留的规则

1. **课程三个 ID 不能混用**：
   - `content.id` → `clazzId`
   - `content.course.data[0].id` → `courseId`
   - `content.cpi` → `personId`

   任意一个缺失就跳过该课程，避免打开空白页或错误课程。

2. **不要按 `isretire` 预过滤课程**：该字段可能缺失。一律请求课程页；没有“待完成任务点”区块就返回 0。

3. **任务点只统计叶子章节**：父节点的 `knowledgeJobCount` 是子节点汇总，直接求和会重复计数。必须先按 HTML 文档位置排序，再排除后面存在更深层任务点的父节点。

4. **兼容扁平和嵌套课程结构**：有的课程任务点全在 `leveltwo`，有的位于 `levelthree`，使用统一的叶子判定逻辑处理。

5. **单课失败不要清空全部课程数据**：保留该课旧缓存，并继续处理下一课；登录态失效则应单独抛出并提示重新登录。

6. **控制请求并发**：作业和考试请求当前采用串行方式，任务点也逐课串行读取，避免不必要的并发请求。

7. **区分失败和成功空结果**：只有同步成功且返回空列表时才清空对应来源；网络或接口失败时保留旧缓存。

## 7. 验证入口

- 离线解析与缓存自检测试位于 `UniversityTodos/Services/JsonSelfTest.cs`，其中包含课程 ID 三元组、课程链接、叶子任务点计数和相对时间缓存往返用例。
- 在线只读自检位于 `UniversityTodos.Desktop/ChaoxingCheck.cs`，通过桌面程序参数 `--cxcheck` 进入，使用本机已保存的学习通会话打印每门课的未完成任务点及明细。
- 更完整的接口实测记录、HTML 示例、正则和移植验收清单位于 `docs/三源作业获取实现规格.md` 第 3 节。
