# 鸿蒙端迁移开发文档

> 项目：大学事项综合待办（UniversityTodos）  
> 代码基线：v1.4.7  
> 审查范围：解决方案、共享模型与服务、桌面/Android 宿主、主要视图、数据文件、后台提醒、备份更新、现有规格与自检入口  
> 文档性质：依据当前代码形成的迁移实施规格；**尚未进行 HarmonyOS 真机或模拟器验证**。涉及系统 API 的条目，开工时须按锁定的 HarmonyOS/API 版本复核。

## 1. 结论与迁移边界

### 1.1 推荐路线

采用 **HarmonyOS 原生 ArkTS + ArkUI + Stage 模型重写平台层和应用层**，不在鸿蒙上继续引入 Avalonia，也不把现有 Android/WebView 包套壳发布。

可复用的是：

- 三个作业源的端点、请求头、解析规则、登录探测规则；
- 稳定 ID、统一待办模型、缓存结构、筛选排序、提醒去重等业务语义；
- 正方教务、成绩、考试、水电费的解析算法和离线样本；
- 界面信息架构、设计令牌、移动端返回层级；
- 现有自检用例所表达的业务不变量。

必须重写的是：

- 全部 Avalonia XAML、ViewModel 绑定和 `NativeWebView`/`NativeWebDialog` 宿主；
- .NET `HttpClient`、文件存储、DPAPI、Android Keystore、Intent、系统通知和定时循环；
- Windows 托盘、桌面挂件、开机自启、安装器与应用内替换更新；
- 鸿蒙签名、后台调度、通知、数据导入导出和发布链路。

### 1.2 不建议的路线

- **不建议新增 `net10.0-harmony` 宿主**：当前解决方案没有对应 Avalonia 官方平台头，也不能假定 .NET for HarmonyOS 可用。
- **不建议逐行翻译 `MainViewModel`**：该文件约 4200 行且直接依赖 `Avalonia.Media`、`Bitmap`、`Dispatcher`、`NativeWebView` 和 `Window`，应先拆出领域语义，再用 ArkTS 按模块实现。
- **不建议首版引入自建服务端代理**：当前三源均可由客户端 Cookie 直连；代理会新增账密/Cookie 集中存储、合规和运维风险。
- **不建议以“页面能打开”为登录成功**：现有代码已经证明必须探测业务接口或受限页面正文。

### 1.3 首个完整版本的范围

完整迁移应覆盖：雨课堂、学习通、批改网，自建待办，本地勾选/已读/星标/我的一天，搜索、分组与排序，课表和教务导入，考试与成绩，水电费，缓存备份，系统通知及能力受限的后台同步。

以下桌面专属能力不进入鸿蒙首版：托盘、桌面窗口挂件、窗口分栏拖动、开机自启、Windows 安装器和 zip 替换更新。鸿蒙服务卡片可作为后续独立需求，不能把它当作桌面 `WidgetView` 的直接等价物。

### 2.4 审查发现的既有边界，不能在鸿蒙文档中误写为已解决

1. **Android 三源会话不是全部加密。** `SessionStore`、`ChaoxingSessionStore`、`PigaiSessionStore` 在非 Windows 平台直接写明文 JSON；Android Keystore 只接入 `CredentialStore` 及教务/统一认证等使用它的存储。鸿蒙必须把所有会话统一接入 HUKS，不照搬这一降级。
2. **Android 自动同步不是可靠原生后台任务。** 当前是 .NET 进程内 `Task.Delay` 循环，进程回收后不能承诺继续同步。鸿蒙应明确区分“系统定时提醒”和“尽力而为的后台同步”。
3. **教务与统一认证的 Android Cookie 显式恢复仍有缺口。** 现有安卓文档也注明相关真机验收未完成。鸿蒙必须把 ArkWeb Cookie 的读取、恢复、删除、跨域隔离列为前置 PoC。
4. **新作业基线当前主要在内存。** `AutoSyncService` 的 `_seen`/`_baselineEstablished` 不持久化；`ReminderState` 虽有 `KnownIds` 字段，但自动同步未使用。鸿蒙若让 UI 与后台任务都同步，必须改为共享且持久化的基线，否则容易重复通知。
5. **静默账密登录并非移动端通用能力。** Android 不启用桌面后台 WebView 登录路径。鸿蒙首版统一以前台官方网页登录为主，直接 POST 登录放到后续可选项。
6. **Browser/iOS 只是模板头。** 不能据其存在推断跨平台能力已经验证。
7. **现有测试以自检入口为主。** `--jsoncheck`、在线 `--cxcheck`/`--pigaitest`、界面 `--androidcheck` 都很有价值，但不能直接作为鸿蒙测试运行；需要把样本和断言移植到鸿蒙测试工程。

## 3. 目标架构

### 3.1 技术选型

- 语言与 UI：**ArkTS + ArkUI 声明式组件**。
- 应用模型：**Stage 模型，EntryAbility + 页面路由**。
- 网络：HarmonyOS NetworkKit HTTP；所有第三方站点请求使用统一客户端封装。
- 网页：ArkWeb，仅用于登录、教务、水费和站内作业页。
- 安全：Universal Keystore Kit（HUKS）保存应用级密钥，加密所有 Cookie 和用户选择保存的账密。
- 本地数据：首版可沿用 JSON 以完成格式兼容；引入系统后台同步前，必须解决跨 Ability/进程的并发写问题，推荐届时转为关系数据库或单一存储服务，JSON 仅作备份交换格式。
- 通知与调度：NotificationKit 负责即时通知，系统提醒能力负责截止/上课时刻，WorkScheduler 一类受约束任务负责尽力而为的后台同步。
- 测试：鸿蒙单元测试/UI 测试框架 + 跨平台 JSON/HTML fixtures + 真机在线只读用例。

> 上表是能力映射，不是对特定 API 版本行为的无条件承诺。尤其是后台任务间隔、提醒重启保留、通知点击路由、Cookie HttpOnly 读取和 HUKS 密钥生命周期，必须在 M0 阶段实测。

### 3.3 状态与并发约束

- `AppStore` 是唯一界面事实源，页面不得各自保存一份待办、课程或登录状态。
- 手动同步、前台自动同步、后台同步共用一个逻辑互斥锁和取消协议；同一时刻最多一个同步事务。
- 三源并行，学习通内部“作业/考试”和“课程任务点”并行；单账号内部仍按现有限流规则执行。
- 同步开始前记录本地状态版本；应用结果时若用户已勾选/星标，保留新操作，不用旧快照覆盖。
- 结果按来源提交，任何一个源失败都不能把另一个源的成功结果或旧缓存清空。
- 后台 Worker 不读取内存单例，不依赖 UI 已启动；它必须从安全存储恢复会话并读取持久化基线。
- 若保留 JSON 存储，写入必须串行、临时文件落盘后原子替换，并处理 UI 与 Worker 同时写的问题；不能只做进程内 Promise 锁就宣称安全。

## 4. 数据契约与必须保留的业务规则

### 4.1 统一待办模型

参照 `../UniversityTodos/Models/TodoItem.cs`、`YktEnums.cs`。

核心字段：

```text
id, kind, title, courseName, subject, classroomId
dueAt, deadlineAnchor, remainingAtSync
publishedAt, status, done, total, score
sourceUrl, noticeId, priority, tags, note, remindAt, isRead
```

派生规则：

- `effectiveDueAt = dueAt ?? deadlineAnchor + remainingAtSync`。
- 本地勾选存于 `local-state`，不能写进平台 `status`。
- 平台作业自动优先级：距截止 `<= 3 天` 为紧急，`<= 5 天` 为高，`<= 7 天` 为普通，其余为低；逾期也归入紧急；无截止时间为普通。
- 自建事项使用手动优先级；公告不参与截止提醒。
- `source` 由 `kind` 和 ID 前缀推导，不另存一份，避免旧缓存不一致。

枚举数值如需读取现有 JSON，必须保持：

| 枚举 | 数值 |
|---|---|
| `TodoKind` | Homework=0，Announcement=1，Custom=2 |
| `TodoPriority` | Low=0，Normal=1，High=2，Urgent=3 |
| `TodoStatus` | Unknown=0，NotStarted=1，InProgress=2，Completed=3 |
| `WeekParity` | Every=0，Odd=1，Even=2；但现有课表 JSON 使用字符串转换器，实际值为 `Every`/`Odd`/`Even` |

### 4.2 稳定 ID

| 数据 | ID |
|---|---|
| 雨课堂作业 | `hw-{classroomId}-{leafId}`；无 leafId 时现有实现退回日志 activityId |
| 雨课堂公告 | `ann-{classroomId}-{activityId}` |
| 学习通作业 | `hw-cx-work-{taskrefId}` |
| 学习通考试 | `hw-cx-exam-{taskrefId}` |
| 批改网作文 | `hw-pg-{rid}` |
| 自建待办 | `man-{32 位无连字符 GUID}` |
| 课表展开课次 | `{scheduleItemId}:{yyyy-MM-dd}` |
| 学习通课程身份 | 复合键 `courseId + clazzId`，`personId` 仅作课程页参数 |

ID 用于去重、选中恢复、新作业判定和本地标记。标题变化不得生成新 ID；不同课堂的同名同截止作业不得跨课堂合并。

### 4.3 缓存与本地状态

`todos.json` 保持以下来源通道：

- `Homework`：雨课堂去重合并**前**的条目；
- `Chaoxing`：学习通作业/考试，保存“基准 + 相对量”；
- `Pigai`：批改网；
- `Announcements`：雨课堂公告；
- `ChaoxingCourses`：课程任务点汇总；
- `CourseSignatures`、`CourseFullSyncedAt`：雨课堂增量基准。

旧版本可能把附加来源也写进 `Homework`，冷启动合并三段后仍需按 ID 去重。

`local-state.json` 包含 `Done`、`ReadAnnouncements`、`Starred`、`InMyDay` 四组稳定 ID。公告已读为“服务端 `hasRead` ∪ 本地已读”。

`manual-todos.json` 必须独立于同步缓存；平台同步绝不能覆盖用户自建事项。

### 4.4 现有 JSON 的跨语言兼容

若支持从 Windows/Android 备份导入，不能只用 JavaScript `JSON.parse` 就假定完成：

- `DateTimeOffset` 是 ISO 8601 字符串，可能带 `+08:00` 或其他偏移；统一转为 Unix 毫秒保存和比较。
- 教务 `DateTime` 没有明确偏移，按学校业务时间（当前实现为北京时间）解释。
- `TimeSpan RemainingAtSync` 是 .NET 字符串，不是毫秒数；需兼容 `[-][d.]hh:mm:ss[.fffffff]`，并用真实备份样本做 fixture。
- `Dictionary<long, ...>` 的 JSON key 是数字字符串，读取后转回整数课堂 ID。
- `HashSet<string>` 是字符串数组，恢复时去重。
- 缺失可空字段按 `null`，不得直接转成 `0` 时间戳；有效业务时间区间沿用 2015-01-01 至 2100-01-01。
- 当前 `SchemaVersion = 1`；高于当前程序版本的文件触发只读，不得用旧结构覆盖。

### 4.5 列表筛选口径

参照 `MainViewModel.ApplyFilter`：

- **我的一天**：非公告、非服务端完成，且满足“手动加入 / 已逾期 / 截止日不晚于今天”任一条件；手动加入者在前。
- **计划内**：有截止时间且非服务端完成，可按时间或优先级排序。
- **作业**：全部作业，服务端完成项排后；本地“隐藏已勾选”只过滤本地勾选，不改服务端状态。
- **学习通网课**：独立课程通道，不生成几十条任务点待办；角标是“有未完成任务点的课程数”。
- **公告**：本地/服务端已读排后，再按发布时间倒序。
- **已完成**：服务端完成的作业 + 本地已勾选自建事项。
- **全部**：排除服务端已完成平台作业，保留其他可见事项和未读公告。

搜索范围为标题、课程、学科、备注和标签；分组支持不分组、按来源、按课程，设置重启后保留。

## 5. 数据源迁移规格

完整端点和样本以 `三源作业获取实现规格.md` 为准；本节规定鸿蒙实现不可省略的行为。

### 5.1 通用 HTTP 层

统一实现 `HttpSourceClient`：

- 支持 GZip/Deflate、显式 Cookie 请求头、重定向、取消和超时；雨课堂 45 秒，学习通/批改网 30 秒。
- 保留桌面浏览器 UA、各源 Referer；不要因运行在手机上就改成手机 UA，站点可能返回不同页面。
- 雨课堂请求带 `xtbz: ykt`；POST 带 `X-CSRFToken`。
- 会话 Cookie 由安全存储显式注入，不依赖 HTTP 客户端与 ArkWeb 自动共享 Cookie。
- 响应记录只保留 URL 路径、状态码、耗时、解析数量和错误类型；不得记录 Cookie、账密、完整响应正文。
- JSON 数字字段使用宽松读取：数字、数字字符串、空串、null、布尔及个别日期字符串都要按现有 `YktNumber` 规则处理，单个坏字段不能拖垮整门课。
- 所有站点接口均为非公开契约。解析失败应产生可诊断警告，而不是把空列表当作真实空数据。

认证失效判定：

| 来源 | 判定 |
|---|---|
| 雨课堂 | HTTP 401，或正文含 `Cookie has no sessionid` |
| 学习通 | 即使 HTTP 200，正文含登录页 `<title>登录</title>` 或 `passport2.chaoxing.com/login` 也视为失效 |
| 批改网 | 即使 HTTP 200，正文含 `请先登录` 也视为失效 |

### 5.2 雨课堂

参照 `YktApiClient.cs`、`SyncService.cs`。

端点链：

1. `GET /v2/api/web/courses/list?identity=2`；
2. `GET /v2/api/web/classroom_archive`，合并归档班级；
3. 每课 `GET /v2/api/web/logs/learn/{classroomId}`；
4. 全量路径读取章节树 `/mooc-api/v1/lms/learn/course/chapter`；
5. `POST /mooc-api/v1/lms/learn/course/pub_new_pro` 获取权威完成状态；
6. 必要时读取 `leaf_info/{classroomId}/{leafId}/` 补发布时间；
7. 未读计数和“全部已读”是独立通知中心能力，不用它替代学习日志的 `hasRead`。

作业只处理日志 type 5、19，公告处理 type 9，忽略 type 14。完成状态只能来自 `leaf_schedules`：缺失或数字形态为未知，不得用“已过期”猜完成。其键是章节项 `id`，不是 `leafinfo_id`。

增量规则：

- 对作业日志的 `id/type/title/create_time/leaf_id/score_d` 计算 SHA-256 签名；
- 签名相同、该课有缓存且距全量校验不超过 24 小时，只刷新完成进度；
- 超过 24 小时强制读取章节树和详情；
- `CourseFullSyncedAt` 只在章节树成功的全量路径刷新；
- 单账号请求串行并保留每请求约 200ms 节流；
- 当前学期课程返回 0 门时保留旧缓存并警告，不能用空结果覆盖；
- 单课日志失败时保留该课旧条目，且不更新该课签名。

链接规则：

- 课程：`/v2/web/studentLog/{classroomId}`；
- 公告：`/v2/web/noticeView/{classroomId}/{noticeId}?identity=0&type=9`，noticeId 来自日志 `courseware_id`；
- 试卷：`/v2/web/exam/{classroomId}/{examId}`，examId 来自 `courseware_id`；
- 章节作业：`/v2/web/exercise/{classroomId}/{leafTypeId}/{skuId}`。

## 6. 登录、ArkWeb 与外链

### 6.1 登录策略

首版统一采用“应用内官方页面 + 用户亲自登录 + 业务探测确认 + Cookie 加密保存”：

| 来源 | 入口与确认 |
|---|---|
| 雨课堂 | 官方登录页；手机上自动切换账密/短信/邮箱，不强迫用户扫描自己屏幕的二维码；课程接口 200 后读取 `sessionid`/`csrftoken` |
| 学习通 | 官方 passport 页面；确认有效 `_uid` 并用业务页复核 |
| 批改网 | 官方首页或微信 OAuth；轮询未完成作文页，正文不再是“请先登录”后才保存 Cookie |
| 教务 | 用户配置的学校 HTTPS 登录页；保存 `JSESSIONID`/`route`，账密不默认保存 |
| 统一认证/水费 | 学校统一认证及水费站点；确认水费表格可读后保存相关域 Cookie |

学习通 `fanyalogin`、批改网 RSA 直接 POST、统一认证自动填表可作为后续增强，不应阻塞首版。若实现，必须提供“验证/双因素/扫码时转前台”的回退路径，且保存账密需用户明确选择。

### 6.2 `WebBridge` 必须提供的抽象

```text
navigate(url)
onNavigationStarted / onNavigationCompleted
evaluateSyncScript(script) → string
readCookies(url) → Cookie[]
writeCookies(url, cookies)
clearCookies(domainRules)
setExternalWindowBehavior(sameWebView | externalBrowser)
close()
```

实现约束：

- 导航开始关闭“页面就绪”闸门，导航完成后再执行脚本；页面跳转期间脚本失败应重试而不是导致登录状态错乱。
- 不假设 ArkWeb 与 Avalonia 一样会 await Promise。统一采用“脚本同步返回；异步 fetch 写 `window.__utResult`；ArkTS 轮询读取”的协议。
- 登录探测不能只监听导航完成，用户输入期间可能没有新导航。
- 读取 HttpOnly Cookie、跨子域写入和按域删除必须真机验证。不要把整串 `a=1; b=2` 当成一条 Set-Cookie 写入。
- 雨课堂主域与答题子域不共享 host-only Cookie 时，逐条铺 Cookie；失败则允许用户在答题页重新登录。
- 新窗口请求在同一 ArkWeb 内导航，避免教务 `target=_blank` 打开失控窗口。
- 释放页面时取消轮询、释放 Web 组件并退订事件，防止旧页面继续写新页面状态。
- Release 包关闭 Web 调试；日志不得输出页面表单值和 Cookie。

### 6.3 退出登录

退出必须同时处理：

1. 停止该源相关同步；
2. 删除 HUKS 加密会话和可选账密；
3. 清理 ArkWeb 中该源 Cookie；
4. 清除该源缓存条目、课程数据和对应本地状态；
5. 重置新作业基线，避免换账号继承旧账号状态。

不能为清一个站点而全清所有站点 Cookie。若系统只能全清，需按域备份其他会话并验证恢复，否则改为逐条过期。

### 6.4 打开站内页面与外部应用

- 雨课堂/学习通作业优先在应用内 ArkWeb 打开，以复用登录 Cookie；其他链接使用系统浏览器。
- 对雨课堂 App 的深链只能作为可选增强；当前 Android 的 `app://yuketang` 不能证明鸿蒙 App 也注册相同路由。
- 外链仅允许 `https`；自定义 scheme 必须白名单并失败回落浏览器。
- 通知点击通过 Want 参数携带内部 `todoId` 或页面路由，不只写外部 URL。

### 7.2 HUKS 加密方案

- 每个安装生成不可导出的应用密钥，建议别名 `UniversityTodos.Harmony.v1`；算法可采用 AES-256-GCM，随机 IV，认证标签随密文保存。
- 外层可继续采用 `{ "protected": true, "data": "<base64>" }` 形态，但应增加 `protectionVersion` 以便未来轮换；密钥、IV、密文格式需在代码中唯一实现。
- HUKS 密文与 Windows DPAPI、Android Keystore 密文**互不通用**。导入其他平台备份时跳过这些文件并提示重新登录，不能把密文当明文解析。
- 解密失败按未登录处理并记录不含敏感值的原因；不要自动删除无法解密的原文件，避免暂时性系统异常造成数据丢失。
- 账号、密码、Cookie、完整会话文件不得进入日志、崩溃附件、界面诊断文本或发布 fixtures。

### 7.3 备份与跨平台导入

保留现有白名单、重复条目拒绝、临时目录、失败回滚思路，并补充：

- 只接受白名单文件的基本名，忽略目录，防止 Zip Slip；
- 限制条目数、单文件大小、总解压大小和压缩比，防止压缩炸弹；
- 先校验全部 JSON 和 SchemaVersion，再提交；失败恢复到导入前状态；
- 默认“跨设备备份”排除会话与账密；若提供“本机完整备份”，也必须说明 HUKS 密文换机/卸载后不可恢复；
- 从 Windows/Android 导入时接受非敏感 JSON，跳过所有 `protected=true` 的会话/凭据，并给出需重新登录的来源清单；
- 壁纸本地路径不跨平台恢复，桌面挂件位置等字段仅忽略，不影响其他设置。

## 9. 通知、提醒与后台同步

### 9.1 拆成三条链路

| 链路 | 数据 | 推荐实现 | 可靠性表述 |
|---|---|---|---|
| 新作业/低电量通知 | 网络同步结果 | 受约束后台同步 + 即时系统通知 | 尽力而为，不承诺准点 |
| 截止/显式待办/上课提醒 | 已缓存的绝对时间 | 系统提醒调度 | 应由系统在时间到达时触发 |
| 每日逾期汇总 | 本地缓存和每天配置时刻 | 每日系统提醒或前台补算 | 每天最多一条，跨重启去重 |

不要把所有功能继续实现为应用内 30 秒轮询。应用被杀后，进程内计时器都不可靠。

### 9.2 提醒规则

参照 `ReminderRules.cs`：

- 有显式 `remindAt` 时只走显式提醒，不叠加默认截止提醒；
- 默认截止提醒目标窗口为 `[due - dueSoonMinutes, due]`；
- 去重键分别为 `{id}|{dueUnixMs}`、`{id}|{remindAtUnixMs}`，改期后允许重新提醒；
- 挂起恢复只补发错过不超过 30 分钟的截止/显式提醒；
- 服务端完成、本地勾掉和公告不提醒；
- 逾期汇总按本地日期和配置时刻去重；
- 上课提醒已上课则不补发；其去重键为展开课次 ID。

每次同步、编辑待办、修改提醒设置、导入课表或换学期后，统一重建系统提醒：先计算期望集合，再新增/更新/取消失效项，不能只追加不取消。

### 9.3 后台同步设计

`SyncWorker` 执行步骤：

1. 从 HUKS 安全存储恢复三源会话；
2. 获取跨 UI/Worker 的同步锁；
3. 读取缓存和持久化新作业基线；
4. 只调用无 ArkWeb 依赖的雨课堂、学习通、批改网和电费客户端；
5. 原子提交缓存与基线；
6. 仅对基线之后新增的未完成作业、以及新进入低电量集合的房间发通知；
7. 会话失效时保留缓存，只发“需要重新登录”的低频提示，不循环报警。

教务、水费和需要前台网页的登录刷新不进入 Worker。网络不可用、系统省电限制或任务未调度时，界面要显示“上次成功同步时间”，不能声称后台始终在线。

### 9.4 通知交互

- 首次进入提醒设置时解释用途并请求通知授权；拒绝后保留应用内提醒状态，不反复弹权限框。
- 点击新作业/截止通知进入对应待办详情；上课通知进入当天课表；低电量进入水电费页。
- 通知 ID 应稳定可取消，不能使用每次进程启动都从 0 自增的 ID。
- 通知正文不包含账密/Cookie；作业标题和宿舍名是否显示在锁屏可由系统通知设置控制。

## 10. UI 与交互迁移

### 10.1 页面结构

沿用 Android 的信息架构，而非桌面三栏：

```text
底部四项：待办 / 课表 / 水电费 / 设置
待办抽屉：我的一天、计划内、作业、学习通网课、考试、公告、已完成、全部
二级页：待办详情、课程详情、自建事项编辑、教务导入、考试/成绩、ArkWeb 页
```

设计令牌参照 `界面设计规格.md`：主色 `#2564CF`，深色 `#4C8DFF`；正文 14vp、辅助 12vp；行圆角 6vp；圆形勾选框；逾期只标红不画删除线；深浅色成对定义。

注意：

- ArkUI 的 vp 与 Avalonia DIP 对应，需按真机密度验证，不能直接当物理像素。
- 全屏二级页使用不透明背景；抽屉和登录页不得透出下层文字。
- 字体重量以 SemiBold 为强调；可继续使用应用图标、Font Awesome 和 Noto Sans CJK，但须随包保留相应许可证。
- 原 `.ico` 不用于鸿蒙包，依据 `app.png` 生成鸿蒙要求的各尺寸图标。
- 壁纸和透明度是可选外观项，不能牺牲正文对比度；首版可先使用不透明表面。

### 10.2 返回与生命周期

返回顺序参照 `MobileShellView.axaml.cs`：

```text
编辑器 → 登录页 → 答题页 → 教务导入 → 考试/成绩 → 设置 →
待办详情 → 课表/水电费 → 抽屉 → 系统默认返回
```

EntryAbility 前台时恢复缓存、会话和必要同步；退到后台时取消纯 UI 计时器和网页轮询；回前台时刷新倒计时、跨天的“我的一天”，并检查是否错过可补发提醒。

页面销毁必须退订事件并取消任务。不得把 EntryAbility、Web 组件或页面上下文放进全局静态对象。

### 10.3 列表状态

- 启动先显示本地缓存，再后台追平；缓存时间与同步中状态同时可见。
- 同步后按稳定 ID 更新，保留当前选中项，避免整页闪烁。
- 待办与学习通课程是两条列表通道，空状态按当前通道计算。
- 课程详情和待办详情互斥，切换导航时清理另一方选中。
- 倒计时有独立的前台分钟级刷新，不依赖同步成功；跨天自动重算。

## 11. 鸿蒙能力映射与前置 PoC

| 能力 | 当前实现 | 鸿蒙候选能力 | M0 必验内容 |
|---|---|---|---|
| UI | Avalonia Fluent/Material | ArkUI | 抽屉、底栏、二级页、深浅色、返回手势 |
| 网络 | .NET `SocketsHttpHandler` | NetworkKit HTTP | 桌面 UA、Cookie 头、重定向、解压、三源真实响应 |
| 网页 | `NativeWebView`/`NativeWebDialog` | ArkWeb | HttpOnly Cookie、同步脚本、跨域、同页新窗口、释放 |
| 安全存储 | DPAPI/Android Keystore | HUKS | 冷启动加解密、错误处理、卸载/换机不可恢复语义 |
| 文件 | .NET File/JSON | 应用沙箱文件、ArkData | 原子替换、.NET JSON 兼容、损坏恢复 |
| 通知 | WinRT/Android Notification | NotificationKit | 权限、渠道/级别、点击 Want 路由、取消 |
| 精确提醒 | 进程内轮询 | 系统提醒调度 | 杀进程、重启、改期取消、时区 |
| 后台同步 | `Task.Delay` | WorkScheduler 等受约束任务 | 杀进程后调度、网络条件、执行时长、与 UI 互斥 |
| 外链 | Intent/`Process.Start` | Want/系统浏览器 | HTTPS、失败回落、返回应用 |
| 导入导出 | StorageProvider/zip | 系统文件选择器与压缩能力 |  SAF 式 URI 读写、白名单、回滚、大小限制 |
| 发布 | APK/EXE/zip | HAP/App Pack、应用市场 | 签名、版本号、设备安装、市场更新 |

网络权限需要 `ohos.permission.INTERNET`。通知、提醒和后台相关声明/授权按目标 API 版本的官方模板配置，不能直接复制 Android 的 `POST_NOTIFICATIONS`、Service 或 WorkManager 配置。

**M0 未通过前不得宣称的功能**：后台可靠同步、杀进程提醒、跨进程 Cookie 恢复、跨设备恢复登录态。

## 14. 版本、签名与发布

### 14.1 身份与版本

建议保持：

- 显示名：`大学事项综合待办`；
- Bundle 名：`com.CompanyName.UniversityTodos`（若目标平台规则要求调整，需全仓库统一）；
- `versionName` 与根目录 `Directory.Build.props` 的 `<Version>` 一致；
- `versionCode = major * 10000 + minor * 100 + patch`，例如 1.4.7 → 10407。

鸿蒙 `AppScope/app.json5` 不会自动继承 MSBuild 属性。应新增一个版本同步/校验脚本，从 `Directory.Build.props` 读取唯一版本并生成或校验鸿蒙配置；发布时若版本、tag、鸿蒙配置不一致则拒绝出包。

### 14.2 更新方式

现有 `UpdateService` 只选择 `win-x64` zip，更新替换器也是 Windows PowerShell，不可复用。

鸿蒙优先使用应用市场更新。内部分发时，“检查更新”只可查询版本并打开签名包下载页/市场详情，下载后由系统安装器处理；应用不得自行替换运行中的 HAP。GitHub/Gitea 的发布令牌只存在于发布环境，不进入鸿蒙应用。

建议产物命名：

```text
UniversityTodos-v1.4.7-harmony.app   # 市场发布包，按实际工具链输出
UniversityTodos-v1.4.7-entry-signed.hap  # 内部测试用签名 HAP
```

### 14.3 合规与隐私

发布前准备：

- 说明三源和教务均为非公开网页接口，站点变更可能导致功能失效；
- 明示收集/保存的数据仅包括用户主动登录产生的会话、可选账密、课程和本地待办，不上传自建服务器；
- 列明网络、通知、后台运行等权限用途；
- 若保存账密，提供单独开关、随时清除和 HUKS 保护说明；
- 附带 Font Awesome、Noto Sans CJK 等第三方资源许可证；
- 检查学校及第三方站点使用条款，不绕过验证码、访问控制或加密参数，不批量抓取无关数据。

## 15. 主要风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 非公开接口/网页改版 | 同步为空或字段错位 | fixture、逐源警告、保留旧缓存、在线只读诊断、版本快速修复 |
| ArkWeb Cookie 与 HTTP Cookie 不一致 | 登录成功但 API 未登录 | 显式 CookieBridge，业务探测确认，M0 真机验证 |
| 后台任务受系统限制 | 新作业通知延迟 | 系统提醒与网络同步分离，展示最后同步时间，不承诺实时 |
| UI/Worker 并发写缓存 | 数据回滚、重复通知 | 单一同步事务、持久化基线、原子提交，必要时改数据库 |
| JSON 跨语言时间格式不一致 | 截止时间和提醒错误 | 统一 Unix 毫秒内部表示，.NET TimeSpan/ISO fixture |
| 误把本地勾选当服务端完成 | 展示虚假进度 | 两套状态永远分开，详情明确“应用内标记” |
| 空响应覆盖旧缓存 | 用户作业暂时消失 | 来源状态机、空课程保护、逐课/逐源旧缓存回退 |
| 明文敏感数据 | 账号被接管 | 全部会话 HUKS，无降级，日志脱敏，跨设备不恢复密钥 |
| 直接翻译大型 ViewModel | 状态分叉、无法维护 | 按领域模块重写，AppStore 唯一状态入口 |
| 过早承诺全功能 | 后台/网页能力无法验收 | M0 先行，未实测能力不写成已完成 |
